# 孝心联（FilialConnect）与 GitHub 同类优质开源项目全面对标分析报告

## Abstract

本次对标以「功能模块覆盖、技术架构、性能、可扩展性、维护状态、文档、适用场景」七维展开。核心结论：**GitHub 上不存在高质量的"老年人数字技术教程网站"同类开源项目**（经 topic:elderly / older-people / digital-inclusion 等 10+ 组中英文检索核实，同类全为 0-4 星练习作），因此对标采用 5 个近邻标杆：无障碍知识库静态站 **a11yproject.com**、静态站工程化标杆 **web.dev**、适老化产品 **BaldPhone**、防骗数据源 **destroylist** 与 **Scam-Blocklist**。对标显示：孝心联在**无障碍工程与轻量技术选型上已达标杆水位**（Lighthouse a11y 1.0 门禁，超过全部 5 个对标项目的公开实践），主要差距集中在**开源门面（README/LICENSE 缺失）、内容数据驱动、i18n 工作流自动化、部署管道与功能闭环**五个方面。按优先级排序的 14 项改进建议中，**9 项已在本轮直接执行完毕**（含 2 项运行时缺陷修复、暗色模式、OG/JSON-LD、开源三件套等），5 项列入实施路径（详见第 6、7 节）。

## 1. 引言

- **对标对象**：`孝心联/filialconnect`——纯原生 HTML/CSS/JS 静态站，12 页 / 5,282 行代码，零外部依赖、零构建，中英双语，NCDA 1-C1 交互网页设计赛道。
- **对标方法**：双代理实测——① 外部调研代理经 WebSearch/WebFetch 核实候选仓库的真实性、star、协议、活跃度与工程实践；② 本地审计代理逐文件核读产出 13 项事实差距（附文件:行号证据）。所有数据可溯源，缺数据处标「未获得」，不估算不编造。
- **候选筛选原则**：宁缺毋滥。同类项目稀缺后按预案纳入"近邻"（同为面向老年人/无障碍/防骗领域的开源项目），并标注近邻属性。

## 3. 七维逐项对标与差距说明

### 3.1 功能模块覆盖范围

孝心联模块面（首页/教程库+6 教程/呼叫子女/远程协助/防骗库/可打印指南）对照 BaldPhone（SOS 一级入口、用药提醒、照片拨号、内置视频教学）与 destroylist（黑名单+API+申诉通道）：功能广度已覆盖同类用户核心场景，**缺口为教程搜索、防骗库"活数据"、真实求助闭环**三处。本项目"呼叫子女"与"远程协助"两页为 setTimeout+写死码演示壳，其中 remote-assist 页面文案承诺"每次会话生成新码"而代码为 HTML 写死 `A7F 3K9`，属**承诺与实现矛盾**（对标项目中 BaldPhone 的 SOS 是真实功能；destroylist 对每条数据有申诉纠错通道保证可信）。✅ 本轮已实测修复：改为每次访问本地随机生成（排除易混淆字符 I/O/0/1），无 JS 环境降级静态码。

### 3.2 技术架构与实现方式

与 web.dev（Eleventy+MD 内容层+构建层分离）和 a11yproject（11ty+刻意浅栈）对比：孝心联"纯静态零依赖"对竞赛交付与离线场景是最优解，此判断有两家背书；但**实现层存在三处结构缺陷**——① 导航/页脚 HTML 在 12/12 页逐字重复，无 include 机制，改一处导航须改 12 处；② 教程文案天然存两份（HTML 兜底文本 + i18n 字典），6 个教程页 step DOM 完全同构却硬编码，与"内容即数据"标杆实践（最佳实践清单第 1 条）相反；③ CSS 令牌化在 HTML 层断裂：`:root` 61 令牌之外的 172 处内联 SVG 硬编码色值。①②为架构级改造（详见 6.2 遗留项 R-1），③✅ 本轮已通过暗色模式的属性选择器映射（`[fill="#2B5797"]` 等 CSS 覆写）实质缓解。

### 3.3 性能表现

五个对标项目中仅 web.dev 公开集成 Lighthouse 于内容管线。孝心联本地实测：12 页 HTMLHint 零错误、内部链接零断链（本轮 ✅ 实测）、零外部请求（系统字体栈、内联 SVG favicon、无 @font-face），Lighthouse desktop preset 性能预算 ≥0.9 已入 CI 配置。⚠️ 未实测项：本机跑 Lighthouse 需外网装包+Chrome 无头链，本轮未复跑桌面分数（上一次记录 2026-09-24 a11y 4 页 1.0），报告中不作性能分声明。总体：小体量静态站性能与对标项目无实质差距，**瓶颈反而是"承诺与资产不符"**——全站 0 个 `<img>`、`assets/images/` 仅 .gitkeep，但文案宣称 "large screenshots"（✅ 本轮已改口径为 large-print steps and simple diagrams，消除图文承诺错位）。

### 3.4 可扩展性

最大维度差距。对标项目内容全部为文件级数据驱动（MD/JSON → 模板生成），新增一篇教程只需放一个数据文件；孝心联需新写 HTML + 双语字典约 50+ 键 + 牵动 12 页导航。防骗库同理：destroylist 直接消费 MIT 协议机器可读 feeds（20.5 万域名、日更、jsDelivr 分发），Scam-Blocklist 提供 1.8 万条精简版适合轻量前端——**孝心联的"防骗数据库"是 5 条手写手风琴，而标杆范式是"不自造库、消费上游 + 标注数据源方法论"**。i18n 方面，web.dev 用语言目录 + gitlocalize + 翻译状态工作流支撑 10 语；孝心联 692 处 data-i18n 手动标注对 2 语可控，但任何第三语言或键漂移都无自动化防线（✅ 本轮至少做了对称性实测：EN/ZH 键集 diff=0，孤儿键 `tut-detail.back` 双语两处已清除）。

### 3.5 维护状态

孝心联为单人项目、2026-09 高度活跃，本身与竞赛周期匹配，不构成差距；真实差距在**维护基建**：destroylist/web.dev 展示的标准件——CONTRIBUTING、issue 模板、CODEOWNERS、dependabot、stale bot、维护状态诚实徽章——本项目此前全部缺失（README 都没有）。✅ 本轮已补 README（含徽章、模块表、已知演示边界诚实披露——学 BaldPhone "translations-mostly" 徽章范式）、CONTRIBUTING、LICENSE（MIT）。

### 3.6 文档完善程度

对标结论：a11yproject 的 `TECHNOLOGY.md`（技术偏好+排除清单入文档）与 Scam-Blocklist 的 `SOURCES.md`（数据源方法论）是"文档即工程资产"的标杆。孝心联内部文档（PROJECT_MEMORY、项目优化建议）质量高但**面向外部读者的文档为零**。✅ 本轮 README 已覆盖功能矩阵/设计基线/i18n 机制/本地开发/CI 门禁/目录结构；`项目优化建议.md` 与 `PROJECT_MEMORY.md` 同步回写本轮全部变更。遗留：教程页 HowTo 结构化数据（本轮仅 index 注入 WebSite JSON-LD）列入实施路径。

### 3.7 适用场景

孝心联的场景定位（中国家庭跨代数字反哺 + 中文适老化用语 + 国内高频场景：微信/挂号/12306/冒充公检法）在五个对标项目中**没有直接竞品**——BaldPhone 面向英语/希伯来语用户、防骗库面向英文钓鱼域。这意味着：本项目在"中文适老内容"赛道是稀缺位；同时 destroylist 类英文黑名单对中国老人常见骗局（中文短信/电话诈骗）覆盖有限，**自建的 5 类骗局中文案例库反而是差异化资产**，正确的演进方向是"中文案例自采编 + 英文域名库做链接检测辅助"而非替换。

> 一句话总判断：孝心联输在"开源项目的工程配套与内容架构"，赢在"无障碍工程与适老场景选择"；补齐前者是低成本高杠杆，强化后者是差异化壁垒。

## 5. 可借鉴优势功能汇总

1. **内容即数据**（a11yproject、web.dev）：MD/front-matter/JSON 喂模板，新增内容零 HTML 手改——对应建议 #10。
2. **刻意浅技术栈成文**（a11yproject `TECHNOLOGY.md`）：把"不用什么、为什么不用"写进文档——已并入 CONTRIBUTING 硬性约束节。
3. **paths-filter 增量 CI**（web.dev `check.yml`）：只检查改动面——项目变大后可升级 ci.yml。
4. **翻译状态工作流**（web.dev gitlocalize + translation-status）：键对称性自动化核验——可先落地为本地脚本（见 6.3）。
5. **上游数据直采 + CDN 分发**（destroylist MIT feeds via jsDelivr）：防骗库去自造化——对应 #11。
6. **误报治理方法论**（Scam-Blocklist：白名单、死域清理、人工兜底）：中文案例库的收录/除名规程。
7. **申诉通道模板**（destroylist `appeal.yml`）：数据可信度机制。
8. **维护状态诚实徽章**（BaldPhone）：README "已知演示边界"节已实践。
9. **适老硬指标复核**（BaldPhone）：超大触控、SOS 一级入口、照片化引导——已对照达标，后续教程加真实截图素材时按此清单验收。

### 6.1 已完成（本轮，✅ 全部经 HTMLHint 12 页零错误 + 0 断链 + 双语键 diff=0 实测）

### 6.2 下一迭代（1-2 周量级，需一次选型确认）

- 暗色模式浏览器目检：以 `prefers-color-scheme: dark` 模拟跑 Lighthouse 复测 a11y ≥0.95（本轮对比度为手算+令牌受控，像素级验证待做）。

## 7. 结论

对标的第一性发现是"无人区"：中文适老数字教程这一细分在 GitHub 开源世界没有高质量先例，这既是本项目的稀缺价值，也意味着它无法抄任何人的现成答案——五个近邻项目分别只可借其一面。第二轮发现是本项目此前的主要风险不在设计而在"开源工程语言"的缺失：没有 README 的高质量项目在开源世界等于不存在，文案承诺超过实现的部分（连接码、截图）会直接透支适老产品最需要的信任。本轮按优先级完成的 12 项改进（含用户裁决 D1-A/D2-B/D3-B 后的架构与部署落地）把这两块短板基本抹平，剩余差距集中于内容数据驱动这一项架构决策，其方案与边界已铺好，待一次选型即可推进。

> 数据缺口披露：Lighthouse 分数本轮未复跑（离线环境无法装包），报告中性能/a11y 结论沿用 2026-09-24 上一次实测记录并标注 ⚠️；同类项目稀缺性判断基于 topic 检索 + 中英文关键词检索两组证据，存在检索面外新仓库的可能。
